# Report craft

You are designing a **long-form HTML report**, not an interactive app.

Author the report the **user asked for**. The scaffold may still contain leftover demo sections — replace them. Do not keep Vendor Risk / diligence / findings chrome unless that is the topic.

## Hierarchy
1. Cover (title from the user goal, one-liner, date/meta)
2. Executive summary (3–5 sentences; KPI strip only if the data supports real metrics)
3. Numbered sections driven by the topic and available evidence (not a fixed risk/vendors template)
4. Closing / next steps when useful

## Visual rules
- Document flow: readable measure (~65ch), clear H1/H2, generous section spacing
- Print-friendly: light or dark per brief; avoid sticky app chrome and filter bars
- Cite real numbers from `data.json` / research when present — never invent
- Charts only when they answer the topic; no decorative sparklines
- Typography from the design brief; no emoji; no purple glow; no generic Inter-on-white

## Done when
- Feels like a finished PDF-in-browser report on the user's topic
- Scannable in 30 seconds, readable in 5 minutes
- Empty room → honest empty state (not fake diligence content)
